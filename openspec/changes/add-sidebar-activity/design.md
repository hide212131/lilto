## Context

`LiltChatHistory` は sessions と activeSessionId を受け、会話選択・名称変更・削除イベントを送る。`LiltApp` は会話の更新、未読状態、updatedAt 降順の並べ替えを既に管理する。

Main の `ConversationHistoryService.listConversations()` は messages を空配列で返す。`readConversation()` は本文付きで取得できる。Renderer は起動時に一覧を取得し、ローカルの送信・応答・scheduler/heartbeat 更新を sessions に反映する。起動後の外部アプリ更新を常時取得する機能は現状ない。

既存の未コミット変更には日本語フォント修正と別の分割設計がある。実装時はこれらを上書きせず、差分を分ける。

## Goals / Non-Goals

**Goals:** ベルで切り替え、更新の新しい会話からタイトルと本文2行を表示する。保存済み未訪問会話にも対応し、既存の未読・選択動作を再利用する。

**Non-Goals:** 更新イベントをすべて蓄積する通知台帳、独自の会話永続化、未読の永続化、外部アプリの変更監視、フィルターや検索の追加。

## Decisions

### 表示仕様

- サイドパネル上端に見出し「チャット」または「アクティビティ」と、ベルのトグルボタンを配置する。初期状態はチャット一覧。ベルを再度押すと一覧に戻る。
- モードは App の `sidebarView: 'chats' | 'activity'` で保持し、再起動時には初期状態へ戻す。サイドパネル開閉や会話選択では保持する。モード切り替えは会話選択や既読処理を発火させない。
- **設計上の仮定:** アクティビティは1チャットにつき最新状態の1行。同一チャットの更新では行を移動・更新し、重複行を作らない。更新ごとの履歴が必要ならデータモデルが異なるため実装前にこの判断を変更する。
- 行はタイトル14px、本文12px・行高1.5で最大2行、省略表示。更新時刻は既存の相対時刻表記を再利用し、絶対日時を title 属性に載せる。未読は既存の青点を使う。全行の DOM 順を updatedAt 降順、同時刻は createdAt 降順、さらに同値なら元順として安定させる。
- 本文のない新規会話も表示し「まだメッセージがありません」とする。全体が空なら「まだアクティビティがありません」とする。
- 行のクリック・Enter・Space は既存の select-session に接続する。会話表示に成功したとき既存の既読処理を行う。アクティビティ行には名称変更・削除メニューを追加せず、一覧モードで既存操作を継続する。
- トグルに aria-label、aria-pressed とツールチップ、行にフォーカス枠を設ける。アイコンは既存 UI に合わせたインライン SVG とし、色だけで選択状態を伝えない。

### 本文の決定と安全な表示

- sessions にある最後の「pending でなく、空白だけでない表示用メッセージ」を採用する。user / assistant / system / error の表示用 text が対象。progress、thinkingText、tool detail は使わない。
- 送信中の仮メッセージは除外し、その直前の本文を維持する。確定回答や失敗メッセージが入ったら置き換える。表示時刻は既存の session.updatedAt を使用し、独自のアクティビティ時刻を保存しない。
- Markdown は既存依存 marked のトークンから可視テキストを抽出し、リンクはラベル、画像は代替テキスト、コードは本文として扱う。空白・改行を正規化し、描画は Lit のテキスト補間だけを使う。HTML は実行しない。チャット本体のメッセージ配列や本文を加工しない。

### 未訪問の保存済み会話

- 本文を全件起動時に取得する案は起動コストが増えるため採用しない。既存 readConversation IPC を使い、アクティビティ表示中の画面内行と前後の少量だけを IntersectionObserver で必要時取得する。
- App 側でプレビュー専用キャッシュ `Map<sessionId, { updatedAt, status, text }>` と取得キューを持つ。最大同時取得は4件、同じ ID と updatedAt の重複要求はまとめる。取得済み本文を sessions.messages へ混ぜない。表示用の短い text のみ保持する。
- ローカル本文があれば優先する。ローカルの更新経路を通った会話は取得キャッシュを破棄する。起動直後やサーバーから更新された未訪問会話は readConversation の本文から抽出する。
- 応答適用時に会話の存在、要求開始時と現在の updatedAt、要求世代を確認する。古い応答、削除済み会話、破棄済みコンポーネントへの結果は適用しない。モードを閉じたら未開始キューを捨て、実行中要求は完了後に結果をキャッシュするだけにする。
- 読込中は「読み込み中…」、失敗時は「内容を取得できませんでした」とし、失敗行に明示的な再試行ボタンを置く。行自体は常に開ける。失敗を空会話として扱わない。削除時はキャッシュも破棄する。
- 外部常時監視は導入せず、既存アプリ内の送信・応答・scheduler/heartbeat 更新を即時に反映する。新規 IPC や backend の一覧取得コストを増やす変更を避ける。

### 変更箇所と責務

| 箇所 | 変更 |
|---|---|
| `src/renderer/components/chat-history.ts` | 見出し、ベル、行表示、可視行要求、再試行イベント、Observer の解除 |
| `src/renderer/app.ts` | モード、取得要求の配線、更新・削除時の無効化、既存会話選択の再利用 |
| `src/renderer/sidebar-activity.ts`（新規候補） | 純粋な本文抽出とキュー・キャッシュ管理。App の巨大化を抑え、取得関数を注入して振る舞いを単体検証 |
| `test/sidebar-activity.test.js`（新規候補） | 抽出・競合・失敗・取得上限の検証 |
| `scripts/e2e-electron-agent-browser.js` | 切り替え、2行制限、更新順、会話遷移の回帰確認 |

## Risks / Trade-offs

- [本文取得に追加 IPC が必要] → 画面内から必要時取得し、同時数制限と更新時刻キャッシュを使う。
- [古い本文応答が新しい回答を上書きする] → 専用キャッシュと世代検査、ローカル更新時の無効化を併用する。
- [一覧の updatedAt には本文以外の更新も含まれる] → 既存の更新順の契約を維持する。メッセージ単位の厳密なイベント時刻は別機能として扱う。
- [ローカル Electron が過去に隔離された] → 隔離を回避せず、現在の実行可否を確認する。不可ならクリーンな CI でライブ検証後に最終 E2E を行い、未実施を成功扱いしない。

## Migration Plan

保存形式変更はない。実装開始時に GPT-6-Luna / xhigh の設定を確認する。ライブ画面検証、単体検証、全 GUI 変更完了後の最終 E2E の順にゲートを通す。リリースは別途実装再開の指示を受けた後、今回差分だけをコミットし、package と lockfile の版を揃え、未使用の v タグで既存 Release workflow を起動する。両 OS の検証済みインストーラーと GitHub Release 公開を確認して完了とする。戻す場合は機能差分を revert し、新しい修正版を公開する。

## Open Questions

実装を妨げる未決事項はない。1チャット1行、再起動時は一覧、本文は最新の確定メッセージという仮定を採用する。現在の依頼は設計までのため、アプリコード変更・テスト実行・リリースは開始しない。
