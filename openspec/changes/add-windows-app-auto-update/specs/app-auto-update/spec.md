## ADDED Requirements

### Requirement: Windows インストール版で起動時に更新を確認する
アプリは Windows x64 NSIS インストール版で初期表示後に一回だけ非同期更新確認を実施しなければならない（SHALL）。安定版のみ対象とし、ダウングレードを許可してはならない（SHALL NOT）。

#### Scenario: 新しい安定版がある
- **WHEN** 起動後の確認で現在より新しい公開安定版を検出する
- **THEN** 現在版と新版を示し、ダウンロードと後でを選べる案内を表示する
- **THEN** 同意まではダウンロードを開始しない

#### Scenario: 起動時に最新版または接続失敗
- **WHEN** 最新版である、または更新サーバーへ接続できない
- **THEN** 起動と通常操作を妨げず、失敗はログに記録する

#### Scenario: 開発版と macOS
- **WHEN** 非 packaged 実行または macOS で起動する
- **THEN** 自動更新通信を実行せず、macOS に未対応の更新操作を表示しない

### Requirement: メニューから共通の更新確認を使える
Windows はアプリのヘルプメニューとトレイ右クリックに「更新を確認…」を提供しなければならない（SHALL）。

#### Scenario: 手動確認結果
- **WHEN** ユーザーがメニューから確認する
- **THEN** ウィンドウを表示し、確認中、新版あり、最新版、失敗と再試行を区別する

#### Scenario: 操作が重なる
- **WHEN** 起動時確認と手動確認が重なる、または取得中に再度メニューを開く
- **THEN** 通信やダイアログを重複させず、共通状態を表示する

### Requirement: 同意に基づいて検証済み更新を取得する
アプリは明示的同意後のみ取得し進捗を表示しなければならない（SHALL）。ハッシュ不一致の更新をインストールしてはならない（SHALL NOT）。

#### Scenario: ダウンロードと保留
- **WHEN** ユーザーが取得を選び、取得が完了する
- **THEN** 再起動してインストールと後でを提示し、後でを選んでも通常利用を継続できる
- **THEN** 通常終了や OS 終了だけではインストールしない

#### Scenario: 取得失敗と遅延応答
- **WHEN** 取得失敗、容量不足、ハッシュ不一致、またはタイムアウトが発生する
- **THEN** 旧版を維持して再試行を可能にし、古い応答で取得済み状態へ遷移しない

### Requirement: 安全に終了してインストールと再起動を行う
アプリは取得済み更新への再起動操作時だけ、所有する子プロセスと書込を停止して NSIS を起動し、インストール完了後の再起動を要求しなければならない（SHALL）。

#### Scenario: 正常な更新
- **WHEN** 取得済み更新で再起動を選び、終了準備が成功する
- **THEN** 常駐の close 阻害を迂回し、NSIS を一度起動し、完了後に新版が起動する
- **THEN** 会話、設定、skills、scheduler DB と既存インストール先を保持する

#### Scenario: 実行中処理または未送信入力
- **WHEN** 終了準備で実行中処理を検出する、または入力喪失確認で取消する
- **THEN** インストールせず取得済み状態へ戻り、通常利用を維持する

#### Scenario: 終了準備失敗とインストーラー起動失敗
- **WHEN** 所有プロセスを制限時間内に停止できない、またはインストーラーを起動できない
- **THEN** 成功と表示せず、現行プロセスが残る場合は受付・終了フラグを復旧し、復旧不能なら再起動を案内する

### Requirement: 完全な更新成果物だけを公開する
配布工程は exe、blockmap、latest.yml と組込み app-update.yml を検証し、整合した成果物だけを正式公開しなければならない（SHALL）。アプリに GitHub 秘密情報を含めてはならない（SHALL NOT）。

#### Scenario: 成果物欠落や不整合
- **WHEN** metadata が欠落するか version、サイズ、SHA-512、参照ファイルが一致しない
- **THEN** 検証を失敗させ正式公開しない

#### Scenario: 公開途中に失敗する
- **WHEN** draft への全 assets 登録が完了しない
- **THEN** draft を正式公開しない

### Requirement: 実際の更新経路を検証してから完了する
実装完了にはライブ画面、最終 GUI 回帰、および Windows の実 NSIS 更新検証を含めなければならない（SHALL）。

#### Scenario: GUI 機能が実装された
- **WHEN** 更新 GUI を検証する
- **THEN** 最初に live-ui-manual-verification を行い、全 GUI 変更後の最後に npm run e2e:electron が成功し test/artifacts/electron-e2e.png が生成される

#### Scenario: Windows の更新をリリースする
- **WHEN** updater 搭載版 A から次版 B のリリース可否を判定する
- **THEN** 実インストール環境で案内、取得、NSIS、B の再起動とデータ保持、キャンセル、通信失敗、不正ハッシュを検証した証跡がある
