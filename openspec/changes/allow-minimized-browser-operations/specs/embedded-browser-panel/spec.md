## MODIFIED Requirements

### Requirement: 右サイドパネルに共有 1 面のブラウザを表示する
アプリは右側の開閉・リサイズ可能なパネルに、Main が管理する 1 面の `WebContentsView` を表示しなければならない（SHALL）。ページ View はページ用 viewport の矩形のみに配置し、ツールバーとチャットを覆ってはならない（SHALL NOT）。ウィンドウの最小化だけでは、準備済みの View の表示設定・有効な bounds・renderer／文書の epoch を変更してはならない（SHALL NOT）。

#### Scenario: 幅の保存と制約
- **WHEN** ユーザーが右ハンドルをドラッグまたは左右キーで変更する
- **THEN** 希望幅（320〜960、既定 480）を `lilto-browser-panel-width.v1` に保存し、ウィンドウ縮小では保存値を書き換えない
- **THEN** チャットは最小 320 を確保し、足りない場合は左サイドバーを閉じてブラウザを優先する

#### Scenario: 収まらない場合
- **WHEN** チャット 320 とブラウザ 320 を確保できない
- **THEN** ブラウザを一時非表示にして「ウィンドウを広げてください」を表示し、全面オーバーレイに戻さない

#### Scenario: モーダル表示
- **WHEN** 設定・更新ダイアログ等を表示する
- **THEN** Main が View を隠した ACK 後にモーダルを描画し、閉じた後に有効な bounds を受信してから再表示する

#### Scenario: 最小化と復帰
- **WHEN** ウィンドウを最小化する
- **THEN** 最小化に伴うゼロサイズ等の測定で有効な操作面を上書きしない
- **WHEN** 最小化から復帰する
- **THEN** 実ジオメトリが測定時と同じなら再測定せず、異なる場合だけ新しい測定を待つ
- **AND** 最小化中の測定通知は animation frame が走らなくても期限付き timer で送られる
